EJEMPLO PRÁCTICO

¿Qué pasa cuando envías “Hola”?

ORIGENAna · 192.168.1.10Wi‑Fi · MAC AA:10
→
REDSwitch/AP → Router → Internetvarios enlaces y saltos
→
DESTINOLuis · servidor de mensajeríaIP 203.0.113.20
  1. 7
    Aplicación crea el dato

    Ana escribe “Hola”. La app añade información propia: usuario destinatario, conversación y contenido. Si fuera una página web, aquí intervendría HTTP/HTTPS.

  2. 6–5
    El dato se prepara y la sesión se mantiene

    El texto se codifica, por ejemplo en UTF‑8; puede cifrarse con TLS y comprimirse. La sesión identifica el diálogo activo con el servicio.

  3. 4
    Transporte agrega puertos

    TCP crea un segmento con puerto origen temporal y puerto destino del servicio. Numera los bytes, espera confirmación y retransmite si algo se pierde. Una app en tiempo real podría elegir UDP.

  4. 3
    Red agrega direcciones IP

    IP crea un paquete con 192.168.1.10 como origen y la IP del servidor como destino. El host compara la red destino; como es externa, envía el paquete a su gateway.

  5. 2
    Enlace crea la primera trama

    Wi‑Fi encapsula el paquete usando direcciones MAC locales. La MAC destino es la del punto de acceso o gateway, no la MAC final de Luis.

  6. 1
    Física transmite bits

    La tarjeta convierte la trama en señales de radio. El punto de acceso las recibe y el switch mueve la trama hacia el router.

  7. R
    Cada router cambia la envoltura local

    El router elimina la trama, examina la IP destino, elige el siguiente salto y crea una trama nueva. Las MAC cambian en cada enlace; las IP identifican los extremos durante el recorrido.

  8. ↑
    El destino desencapsula

    El servidor recibe bits → trama → paquete → segmento → datos, verifica cada cabecera y entrega “Hola” a la aplicación. La respuesta vuelve mediante el mismo proceso, aunque puede tomar otra ruta.

“Hola”＋ TCP＋ IP＋ Wi‑Fi/Ethernet→ bits

ENCAPSULAMIENTO Y TIPOS DE DATOS

El mismo mensaje, cuatro envolturas

Al bajar por la pila, cada capa agrega información de control —una cabecera y, a veces, un tráiler— a la unidad recibida. El destino elimina esas envolturas en orden inverso: desencapsulamiento.

¿Una trama o un conjunto de tramas?

Una trama es una sola unidad de capa 2 que transporta un paquete —o parte de él— por un enlace local. Un conjunto de tramas es solo una colección o secuencia de varias unidades; no constituye una PDU nueva ni reemplaza al segmento o al paquete. En cada salto, el router quita la trama recibida y crea otra para el siguiente enlace, mientras el paquete IP continúa su recorrido.

04

HARDWARE DE RED

Quién toca qué

⌁
Hub / repetidorCAPA 1 · BITS

Regenera y replica señales hacia todos los puertos. No interpreta direcciones.

⇄
Switch / puenteCAPA 2 · TRAMAS

Lee direcciones MAC y reenvía tramas dentro de una LAN. El puente conecta segmentos; el switch es un puente multipuerto.

⌬
RouterCAPA 3 · PAQUETES

Interconecta redes, examina IP, elige la ruta y reencapsula el paquete en una trama nueva por cada salto.

◇
GatewayCAPAS SUPERIORES

Traduce entre protocolos o aplicaciones diferentes y puede establecer comunicación entre sistemas heterogéneos.

OTROS BLOQUES DEL PDF

Usos, impacto y servicios

USOSAplicaciones domésticas

Las redes sostienen comunicación persona a persona, mensajería, radio y video por Internet, teleaprendizaje, redes sociales, wikis, comercio electrónico, IPTV, streaming, juegos multijugador y mundos virtuales.

  • P2P: no depende de una base central; cada participante comparte datos locales. BitTorrent es el ejemplo del PDF.
  • Computación ubicua: integra sensores y conectividad en objetos cotidianos.
  • RFID: etiquetas pasivas, sin batería, que responden a lectores por radio.
MOVILIDADInalámbrico no siempre significa móvil

El documento distingue si el equipo se desplaza y si usa radio: un notebook puede ser móvil usando cable; una red fija en un edificio puede ser inalámbrica.

  • Hotspot: punto de acceso para equipos móviles.
  • 3G/4G y GPS: conectividad y localización en teléfonos inteligentes.
  • NFC: comunicación de campo cercano asociada al comercio móvil.
  • También aparecen redes de sensores y computadoras usables.
IMPACTOAspectos sociales

Internet amplifica debates políticos y éticos. Surgen tensiones entre privacidad, vigilancia, libertad de expresión, derechos del empleador y protección de información empresarial.

  • Cookies y seguimiento de información personal.
  • Anonimato: facilita denuncias, aunque una acusación anónima puede no ser evidencia.
  • Información falsa o mal documentada, spam, virus y derechos de autor.
SEGURIDADCuatro propiedades necesarias

Confidencialidad restringe la lectura; autenticación verifica identidad; autorización define qué puede hacer una identidad; irrebatibilidad evita que una parte niegue una acción realizada.

El PDF recalca que proteger equipos conectados cuesta cada vez más y que muchos problemas provienen de software con fallas.

ESCALALAN, MAN y WAN

LAN: área local, cableado generalmente del usuario y medio compartido o conmutado; Ethernet, Token Ring, FDDI y Wi‑Fi. MAN: alcance metropolitano; WiMAX 802.16. WAN: gran distancia, servicios de operadoras y enlaces punto a punto; el satélite puede ser broadcast.

WAN Y ACCESODel circuito virtual a banda ancha

X.25 fue una red orientada a conexión; Frame Relay la reemplazó con unidades variables; ATM usa circuitos virtuales y celdas fijas de 53 bytes. xDSL lleva banda ancha por el par de cobre y el cable módem por la red de televisión por cable.

INTERREDESConectar redes diferentes

Internetworking une redes que difieren en tecnología, tipo o protocolo. Repetidores trabajan con señales; puentes y switches con tramas; routers con paquetes; gateways traducen protocolos de transporte o aplicación.

TOPOLOGÍASForma física y flujo lógico

Estrella, anillo, árbol sin bucles, malla completa, anillos interconectados y malla parcial describen conexiones. La topología física muestra el cableado; la lógica describe cómo circulan los datos.

  • Unicast: uno a uno.
  • Multicast: uno a un grupo.
  • Broadcast: uno a todos.
  • Anycast: uno cualquiera de varios destinos.
SERVICIOSCONS frente a CLNS

CONS establece un canal, conserva orden y ruta; una falla interrumpe la comunicación. Ejemplos: telefonía, GSM, ATM, X.25 y Frame Relay. CLNS envía sin preparar canal; cada paquete lleva destino, puede variar su ruta y la red puede rodear fallas. Ejemplos: IP y Ethernet.
